# 二阶段实施详细计划：Adaptive Loop Spike（替换默认 loop 的尖峰验证）

> 本文档是二阶段的唯一执行基准。范围来自《[全阶段实施计划](全阶段实施计划.md)》§4.2（v2.0）与 ADR-0012（全面掉头：替换默认 agent-loop）。
> DSH 基线 = **v0.1.2-alpha.1 源码构建**（ADR-0011）。接口事实以 `docs/context/dsh-interface.md` 为准；本文引用处标注【已验证】或【M0 验证】。

## 1. 目标与非目标

### 1.1 目标

1. **v0.1.2 适配三件套**（M0 先行，沿用 ADR-0011 登记，任何方向都绕不开）：③ 插件 patch 移除 storage 插入行恢复 boot；② tool-goal wrapup 时序真实 profile 复核；① 三工具 object schema 补 `additionalProperties`。
2. **OPEN-7 替换 seam 实证**：树外 loop 包经 bundles 层栈替换 `dsh-agent-loop` 的确切机制；替代 driver 职责清单落档。
3. **AdaptiveLoopAgent v0**：实现 Agent contract 的稳定 driver，session 生命周期单实例；三模式 FAST / EXECUTE / VERIFY + 确定性 router + 最小 transition budget。
4. **loop 事件落账**：`gungnir/loop-state` / `gungnir/loop-transition` 命名空间放开（fold 的 `reserved` 拦截解除，additive），`loop/mode-selected` / `loop/transition` 可冷重建出模式轨迹。
5. **四组对照实验 + 继续/熔断门判定**，结论落 stage report。

### 1.2 非目标（显式排除，防范围蔓延）

- LLM router / meta-model；DELIBERATE / RECOVER / FINALIZE 完全体；meta-controller 完整 hysteresis（全部三阶段）。
- 原 Proof-Carrying 八项（五级 Verifier 补全、GoalSpec Compiler、spec 变更、WAITING_EXTERNAL 等，移档三阶段）。
- 物理热插拔（永远禁止，ADR-0012）；任何对 DSH 源码的修改；fork DSH。
- 多 goal、跨 session goal；UI cards、发布与生态（四阶段）。
- **代码层语义猜测**：router 只做公开声明、可审计、可落账的确定性规则，不用关键词/正则嗅探任务文本"该用哪个模式"（Let It Go 铁律）。

## 3. 三模式与 router v0 定义

### 3.1 FAST——能不思考就不思考

便宜模型 / low reasoning。适用：明确问答、单步决定、obvious next action、简单分类。

### 3.2 EXECUTE——模型不一边拧螺丝一边重新思考人生

自动优先 Code Mode / 并行工具，让 runtime 干活；中间工具结果不回灌上下文。直接利用 DSH 已有 Code Mode 能力，不重造。

### 3.3 VERIFY——证明的优先序不能反

deterministic check → cheap verifier → independent LLM judge。spike 期只接 Gungnir 已有 L1/L2 verifier（Prove 层复用，这是一阶段投资的回报）。

### 3.4 router v0（确定性规则）

```text
下一步需要多工具连续执行 → EXECUTE（优先 Code Mode）
存在可机器复验的验收谓词 → VERIFY
否则 → FAST
```

路由规则放 `@gungnir/core` 做纯函数，决策表全单测。WAIT 是运行状态，不算认知策略。

**校准输入（M1 冻结 router 阈值时吸收；来源 [SwitchBench v0 报告](../../tools/experiments/switchbench/results/report.md) 综合判词）**：小型单模块任务面上 baseline（普通 ReAct）全面占优、branch search 类重型策略的固定开销不回本 → router 的默认倾向是"不升级"，只在任务状态卡死 / 高不确定等有证据的场景才允许切重型策略。这是 router 的第一个校准点，即 ADR-0013 修订第 6 条正式冻结的第一设计原则 **Default-to-cheap, escalate-on-evidence（默认不升级，有证据才升级）**。

### 3.5 最小防振荡

单任务模式切换预算上限 + 同模式最少 dwell 一轮（具体阈值 M1 冻结并进 ADR）。完整 hysteresis 五件套（dwell / cooldown / evidence threshold / switch budget / circuit breaker）属三阶段。

## 4. 替换 seam 技术假设（OPEN-7，M0 实证）

- 官方承诺【源码树】：agent loop 与其他部件一样是插件、可从配置替换（`docs/architecture.md:11,59`）；扩展包依赖 dsh-agent 的事件与服务，不依赖 agent-loop 包（`docs/capability-seams.md:507`）；agent-loop 在组合里是 bundles 清单的一行（`apps/cli/composition.md:270`）。
- 候选机制：profile 的 `dsh.profile` bundles 清单中替换 agent-loop 行；或树外包经 `dsh.bundle.patch` 入层后覆盖同 id 行。确切行为 M0 用 `--dump-config` + 真实 boot 实证。
- **driver 职责清单**（替代实现必须完整承担）：agent 生命周期、turn/step 边界、工具调度（含并行与 abort drain）、teardown、resume/fork 支持。M0 勘察 `dsh-agent-loop` 源码整理成清单落档 dsh-interface.md；spike 期允许读其源码作参考，不复制、不修改其包。
- 红线：若 seam 实证发现须修改 DSH 源码才可达 → 触发熔断条款 (b)，回退方案 B（全阶段计划附录 A），写 ADR 复盘。

## 5. 实验协议（预注册先于跑批）

> 平行实验：`tools/experiments/switchbench/`（SwitchBench v0，工作块 9）裁决 H1"异构 Loop 拓扑能否干净 Strategy 化"，其结论是三阶段策略接口设计的输入，与本实验互不依赖、互不等待。

### 5.1 任务集

沿用一阶段跑批器（`tools/experiments`）扩展。任务集以多工具序列执行任务为主（loop 收益所在），辅以问答/研究任务作对照；ground truth 标注流程同一阶段。假验收探针必须模型无关（一阶段教训）。

### 5.2 四组配置

DSH Standard（默认 preset）/ DSH Code-PTC（code preset）/ DSH Workflow / Gungnir AdaptiveLoop（v0 三模式）。

### 5.3 指标（每任务记录）

task success（Gungnir Verifier 层判定）、input/output tokens、LLM calls、tool calls、LLM round trips、wall-clock latency、cache hit、validation failures、instruction violations、loop repetitions、recovery count。token 口径【M0 验证 OPEN-5：`dsh-token-meter` 插件侧可达性】；不可达则退代理口径并在报告写明。

### 5.4 判定门（实验门槛建议值，非已验证事实；跑批前预注册锁定）

task success 不下降，且满足下列至少两项：

- input token ↓ ≥20%
- LLM round-trip ↓ ≥25%
- latency ↓ ≥15%
- 重复无效步骤 ↓ ≥30%

对照基准是 Code/PTC 组，不许只跟 Standard 比。

### 5.5 熔断出口

打不过 Code/PTC → 暂停替换路线，回退方案 B；B3 事件语义破坏 → 红线停止，修到语义对齐才准继续。

### 5.6 对照实验任务面设计输入（SwitchBench 判词，M3 冻结时吸收）

下一轮实验的关键问题不再是 Branch Search，而是 **Router 能否准确判断"什么时候不升级"**（ADR-0013 修订第 6/7 条：Default-to-cheap, escalate-on-evidence；Baseline-Preserving Adaptive Runtime）。SwitchBench 已给第一个负样本：小型 / 单模块 / 测试充分 / root cause 易定位 → **NEVER escalate**（baseline 即最优）。需故意构造正样本组：大型 / 跨模块 / 多个 plausible hypotheses / 局部修复连续失败 / 错误来源不明确 → **SHOULD escalate**。三组对照：Baseline vs Always Heavy vs Gungnir Router。目标形态不是"Gungnir 永远最快"，而是：简单任务 Gungnir ≈ Baseline；困难任务 Gungnir > Baseline；混合任务全集 = 接近 Baseline 的简单任务成本 + Heavy Strategy 的困难任务成功能力。

## 6. 里程碑与时间盒

业余节奏；时间盒超支 50% 触发范围削减而不是延期（沿用一阶段纪律）。核心对照实验（M3）设计为 48–72 小时可完成的体量。

| 里程碑 | 内容 | 时间盒 | 退出物 |
|---|---|---|---|
| **M0 适配与 seam 侦察** | 适配三件套（③②①顺序，ADR-0011）；§14 接缝回归全绿；OPEN-7（替换机制实证）+ OPEN-5（token 可观测性）；driver 职责清单落档；ADR-0013（替换机制）落档 | 4 天 | boot 恢复 + 回归绿 + spike 报告 + 职责清单 |
| **M1 AdaptiveLoopAgent v0** | driver 骨架 + 三模式 + router v0（core 纯函数，决策表全单测）+ loop 事件落账与冷重建 | 5 天 | B3/B4 达成 |
| **M2 跑批器扩展** | `tools/experiments` 四组配置 + 指标采集 + 预注册文档落盘 | 2 天 | B5 前置就绪 |
| **M3 对照实验与判定** | 跑批（48–72h 窗口）→ 统计 → 门判定 → stage report + 三阶段计划修订输入 | 3 天 | B5/B6 达成 |

总计约 14 天纯工期，折合 2–3 周。M0 的 OPEN-7 是全局风险点，放最前面烧掉。

## 7. 测试策略

- **单元（core）**：router 决策表全覆盖；loop 事件 schema/fold（strict replay 含非法 transition 拦截、断序拒绝）。
- **集成**：真实 profile headless 冒烟（沿用一阶段管线）；B3 事件语义对照断言（同一任务在两种 driver 下的事件序列形态比对）。禁止离线 mock 联调。
- **破坏矩阵新增**（沿用 tools/destruction）：

| # | 注入 | 断言 |
|---|---|---|
| D-11 | 策略转换中途 kill 进程 | 冷重建后 loop state 与转换历史完整；不出现双 driver / 半提交状态 |
| D-12 | 高频信号振荡注入 | transition budget 拦截，模式切换数不超上限 |
| D-13 | resume/fork 后续跑 | 事件语义与默认 driver 等价；loop 账本续写正确 |

## 8. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| OPEN-7 发现 seam 不可用或须改源码 | 高 | M0 最前烧；熔断条款 (b) 已预注册回退方案 B |
