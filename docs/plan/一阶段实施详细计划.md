## 1. 目标与非目标

### 1.1 目标（全部来自初步结论第一刀，不得加戏）

1. `/ultragoal <objective>` 命令 → 生成并提交 GoalSpec（**不做**自动苏格拉底澄清；spec 由单次确认或手写文件产生）。
2. 每轮只 commit 一个 action；执行后从 `tools/result` 等 harness 观测点捕获 evidence。
3. 实现 3 类 Verifier：exit code（L1 deterministic）、文件/artifact（L2）、LLM rubric（L4）。
4. Reconcile 闭环：evidence → verify → status 更新 → 决定下一动作/终止。
5. 破坏测试作为第一等交付：改文件、杀进程、DSH 重启后，能从 event ledger 重建状态继续。
6. Ledger schema 设计时预留 `loop/state`、`loop/transition`（三阶段使用，不返工）。

### 1.2 非目标（显式排除，防范围蔓延）

- 苏格拉底澄清系统、多轮 intent 面试（二阶段 GoalSpec Compiler 才做）。
- Contract VM / 完整 versioned plan graph（已裁决不做，见 ADR-0003）。
- L3 external-state、L5 human verifier 的完整实现（L5 仅以 NEEDS_HUMAN 停轮形态出现）。
- plan invalidation 的精细版本管理（一阶段 projection 每轮重生成，仅此而已）。
- 自适应 Loop、propose_loop_transition、多 goal、跨 session goal。
- 任何对 DSH `agent-loop` 或核心包的修改。

## 3. 总体架构

### 3.1 仓库与包结构

```text
dsh-gungnir/
├── pnpm-workspace.yaml
├── package.json                # private，workspace root
├── packages/
│   ├── core/                   # @gungnir/core —— 纯域函数，零 DSH 依赖
│   │   ├── src/schema/         #   GoalSpec / 事件 / verdict 的 zod schema
│   │   ├── src/fold.ts         #   事件流 → GungnirState（strict replay）
│   │   ├── src/reconciler.ts   #   状态机与决策函数（纯函数，决策表驱动）
│   │   └── src/verifier.ts     #   Verifier 契约接口 + 决策辅助（不含实现）
│   └── dsh-plugin/             # dsh-gungnir —— cordis 插件（发布名）
│       ├── src/index.ts        #   apply(ctx)：命令、工具、事件监听
│       ├── src/ledger.ts       #   session 事件 append + 状态缓存 + 冷重建
│       ├── src/evidence.ts     #   tools/result 捕获、文件/exit-code 采样
│       ├── src/verifiers/      #   exit-code / artifact / llm-rubric 实现
│       └── src/surfaces/       #   /ultragoal、/gungnir 命令、gungnir_report 工具
├── tools/
│   ├── destruction/            # 破坏注入 harness
│   └── experiments/            # 20 任务实验跑批与统计
└── docs/
```

分层理由：`core` 不 import 任何 DSH/cordis 模块——fold/replay 与决策必须是可脱离 harness 全量单测的纯函数（这是"从 ledger 重建"可信的前提），也方便三阶段复用。

### 3.2 运行时数据流（一轮的生命周期）

```text
用户 /ultragoal <objective>
   │
   ▼
[spec 阶段] one-shot spec 草案（模型生成 → ask-user 单次确认）或 --spec 文件
   │  append: gungnir/spec
   ▼
[reconcile] Reconciler：生成 plan projection（advisory）→ commit 一个 action
   │  append: gungnir/plan-projection, gungnir/commit
   │  创建/维持 native goal（ctx.goals，armed）
   ▼
[续轮] goal-round-driver 排 <goal_round>（DSH 原生机制【已验证】）
   │
   ▼
[pre-step] Gungnir 的 agent/pre-step 监听器注入 reconcile 指令：
   │        当前 committed action、criteria 状态、evidence 摘要、
   │        "已 PASS 的不要重做"、"claim ≠ evidence" 提醒
   ▼
[执行] 模型在 goal round 内调用工具
   │  tools/result（observe-only【已验证】）→ append: gungnir/evidence
   │  模型可调 gungnir_report → append: gungnir/claim
   ▼
[轮末] agent/turn-stopping / goal round 边界 → Verifier 运行
   │  对相关 criteria 跑 predicate（exit code / artifact / rubric）
   │  append: gungnir/verdict（每 criterion 一个）
   ▼
[reconcile] 纯函数决策（§6 状态机）
   │  append: gungnir/status
   ▼
   ├─ ADVANCE / REPLAN / RETRY → 下一轮（回到 [reconcile]）
   ├─ BLOCKED / NEEDS_HUMAN → 停轮，native goal → blocked/pause
   └─ 全部 PASS → GOAL_REVALIDATION（重跑全部 verifier）→ COMPLETE
        （complete 动作由模型在 goal round 内调用 update_goal 完成，
          Gungnir 只注入"证据已齐，请 complete"指令——authority 合规）
```

### 3.3 与 native goal 的关系（本阶段最重要的接缝决策）

原则：**Gungnir 不重新发明续轮，复用 `goal-round-driver`；不代行 authority，让模型走合法路径。**

- native goal 的 objective 即 Gungnir objective（`/ultragoal` 是 human 命令，创建 goal 走 human 路径，与 `dsh-command-goal` 同构【已验证】）。
- Gungnir 不调用 `update_goal(complete/blocked)` 替模型做主：它通过 pre-step 指令 + 证据状态引导模型自己调用（`tool-goal` 的 complete/blocked 接受当前 goal round 身份【已验证】，模型在 goal round 内调用是合法路径）。
- Gungnir 的 `gungnir/status` 与 native goal phase 保持单向映射：Gungnir COMPLETE/REVALIDATING → 期望 native complete；BLOCKED/NEEDS_HUMAN → 期望 native blocked/pause；不一致时**报警不代写**（fail loud）。

## 4. Ledger 设计（本阶段核心资产）

### 4.1 载体决策

**首选：session log durable events**——通过 `agent.session.append('gungnir/*', payload)` 写入，与 `goal/change` 同构【已验证：goal domain 即此模式】。理由：继承 DSH "session log 是唯一持久权威"铁律；resume/fork/重放机制免费获得；不引入第二持久层。

【M0 验证】两个前置假设，任一不成立则启用备选（独立 JSONL ledger via `ctx.storage`，fold 接口不变）：
- 假设 1：strict replay 接受自定义事件类型（`known-event-types` 是否封闭）。
- 假设 2：compaction 不会裁掉 `gungnir/*` 事件导致不可重建；若会，追加"定期 checkpoint 快照事件"策略（append-only 快照，仍可重放）。

### 4.2 事件 schema v1（M0 冻结）

所有事件共享 envelope：`{ v: 1, ts, ...payload }`；顺序由 session log 序列保证；payload 全部 JSON-safe。

| 事件 | payload 要点 | 说明 |
|---|---|---|
| `gungnir/spec` | `specId, version, objective, successCriteria[], constraints[], nonGoals[], assumptions[], budget` | successCriteria 每项：`{id, description, predicate: {kind, params}, verifierLevel}`。kind ∈ `exit_code \| artifact \| llm_rubric \| human` |
| `gungnir/plan-projection` | `specId, projectionId, steps[], rationale` | advisory 投影，每轮 reconcile 可重生成；steps 每项 `{id, summary, targetsCriteria[], expectedEvidence[]}` |
| `gungnir/commit` | `round, actionId, summary, targetsCriteria[], expectedEvidence[]` | **每轮恰好一个** committed action（一阶段约束） |
| `gungnir/evidence` | `evidenceId, source, ref, digest, ts` | source ∈ `tool_result \| file \| exit_code \| env`；`ref` 指向 `{turn, step, tool, callId}` 或文件路径；大内容只存 digest + locator，不整体入 log（对齐 DSH spill 思路） |
| `gungnir/claim` | `round, actionId, summary, assertedOutcome, evidenceRefs[]` | 模型报告，永远是 claim 不是 evidence |
| `gungnir/verdict` | `criterionId, round, verifier{level, kind}, outcome, detailRef, ts` | outcome ∈ `PASS \| FAIL \| PARTIAL \| INCONCLUSIVE \| STALE \| NEEDS_HUMAN` |
| `gungnir/status` | `specId, phase, satisfiedCriteria[], progressSnapshot, blocker?` | phase ∈ `SPEC_COMMITTED \| EXECUTING \| VERIFYING \| REVALIDATING \| COMPLETE \| BLOCKED \| NEEDS_HUMAN`；progressSnapshot：`{satisfied: m/n, verifiedArtifacts, roundsNoImprovement}` |
| `gungnir/loop-state` *(预留)* | —— | 三阶段使用；一阶段只占命名空间 |
| `gungnir/loop-transition` *(预留)* | —— | 同上 |

### 4.3 Fold 与重建

- `fold(events: GungnirEvent[]): GungnirState` 纯函数：strict replay——畸形 schema、断序 round、非法 phase 转换**立即抛错并停在首个坏事件**（对齐 DSH goal fold 文化【已验证】），绝不静默跳过。
- 运行时内存缓存 `GungnirState`；每次 append 后增量 fold。
- 冷重建：进程启动/会话 resume 时，从 session log 过滤 `gungnir/*` 全量重放。重建是破坏测试的核心断言对象。

## 5. Verifier 契约（3 类）

```ts
// packages/core/src/verifier.ts —— 契约在 core，实现在 dsh-plugin
export interface Verifier {
  kind: 'exit_code' | 'artifact' | 'llm_rubric';
  level: 1 | 2 | 4;                      // L5 human 一阶段只有 NEEDS_HUMAN 出口
  verify(criterion: Predicate, ctx: VerifyContext): Promise<Verdict>;
}
```

| Verifier | 级 | 判定内容 | 实现要点 |
|---|---|---|---|
| ExitCode | L1 | 命令 exit code（+可选 stdout JSON predicate） | 经 harness 的 pwsh 执行器跑（Windows 栈【已验证】），超时上限，stdout/exit code 作为 evidence 落盘 |
| Artifact | L2 | 文件存在 / 内容包含 / JSON-path 谓词 / sha256 | 只读检查；路径限制在 workspace 内（安全边界不越过 sandbox） |
| LlmRubric | L4 | 自然语言成果按 rubric 评分 | 经 `ctx.llm` 调用；强 schema 输出；记录 model id + prompt hash；**结果标记低可信** |

**阶梯强制规则（一阶段版）**：COMPLETE 判定必须至少有一条 L1/L2 verdict 佐证；纯 L4 verdict 不足以支撑任何 criterion 的最终 PASS——只允许 PARTIAL/INCONCLUSIVE。这是"能用 1 绝不用 4"的一阶段可执行形式。

Verifier 触发时机：轮末批量（当前 commit 的 `targetsCriteria`）+ GOAL_REVALIDATION 全量。同 criterion 重跑条件：有新 evidence 或世界状态 digest 变化。

## 6. Reconciler 状态机（纯函数决策表）

```text
SPEC_COMMITTED →（首轮 commit）→ EXECUTING
EXECUTING →（goal round 结束，evidence 收齐）→ VERIFYING
VERIFYING → reconcile() ∈ {ADVANCE, REPLAN, RETRY, BLOCKED, NEEDS_HUMAN, REVALIDATE}
REVALIDATE →（全部 criteria 重跑）→ COMPLETE | 回 EXECUTING
任意态 →（/gungnir pause|clear）→ 停轮
```

决策函数 `reconcile(state, verdicts) → Decision` 的守卫（全部可单测的决策表）：

| 条件 | 决策 | 说明 |
|---|---|---|
| 当前 action 的全部 targetsCriteria PASS 且投影仍有效 | ADVANCE | commit 下一个 action |
| evidence 显示投影前提失效（文件已变、依赖不存在等） | REPLAN | 重生成 projection，留 rationale |
| FAIL 且错误签名与上次相同（transient 判定）且 retry < 2 | RETRY | 重 commit 同一 action |
| 连续 3 轮 `satisfied` 无增长，或重复相同 action，或超 budget | BLOCKED | 写 blocker code，native goal 应 blocked |
| 任一 verdict NEEDS_HUMAN，或谓词无法机器执行 | NEEDS_HUMAN | 停轮等用户 |
| 全部 criteria PASS | REVALIDATE | 全量重跑（防假验收），全 PASS 才 COMPLETE |

辅助守卫（来自 UltraGoal 文档熔断清单）：`roundsNoImprovement ≥ 3`、`budget.remaining ≤ 0`、Verifier 连续 INCONCLUSIVE——三者任一触发即不允许继续 commit，只能 BLOCKED/NEEDS_HUMAN，杜绝无限重规划烧 token。

## 7. 人侧与模型侧表面

### 7.1 命令（`ctx.commands`，human 面，无模型轮【已验证：command-goal 同构】）

| 命令 | 行为 |
|---|---|
| `/ultragoal <objective>` | 触发 spec 草案流程（模型一轮内产出 spec 草案 + ask-user 单次确认） |
| `/ultragoal --spec <path>` | 从手写 YAML/JSON 加载 GoalSpec（实验与精确控制用） |
| `/gungnir status` | 当前 spec、phase、criteria m/n、最近 verdicts、blocker |
| `/gungnir verdicts [round]` | verdict 明细（含 verifier level 与 evidence locator） |
| `/gungnir pause \| resume \| clear` | 控制动词；clear 保留 durable 历史 |

### 7.2 模型侧工具（`ctx.tools.register`）

| 工具 | 用途 |
|---|---|
| `gungnir_report(round, action_id, summary, asserted_outcome, evidence_refs[])` | 上报 claim；明确告知"这是 claim，verdict 由 harness 依据 evidence 裁决" |

一阶段**不提供** `propose_loop_transition`（三阶段产物）。

### 7.3 pre-step 注入内容（每 goal round 一条 directive）

`agent/pre-step` waterfall 返回 `{kind:'enter', messages: [goalRound, gungnirDirective]}`【已验证：pre-step 可重写/追加消息】。directive 内容：committed action（本轮唯一任务）、criteria 状态表（已 PASS 不重做）、可用 evidence 提示、"claim ≠ evidence"提醒、终止条件（何时该 update_goal complete/blocked）。

【M0 验证】与 goal-round-driver 自身 pre-step 监听器的执行顺序（waterfall 顺序 = 插件加载顺序）。若相互干扰：降级方案为 `Agent.inject()` 排队上下文（不与 driver 的 pre-step 抢改写权【已验证：inject 在最近 step 边界被领取】）。

总计约 3–4 周。M0 的两个 OPEN 决策是全局风险点，放最前面烧掉。

## 9. 测试策略

### 9.1 分层

- **单元（core）**：schema 往返、fold 严格性（断序/畸形/非法转换必须抛错）、决策表全覆盖、digest 稳定性。无 mock、无 IO。
- **集成（dsh-plugin）**：真实 dev profile + headless 任务冒烟（`dsh --profile gungnir-dev` 起本地实例）。禁止离线 mock 联调——必须基于真实 DSH 服务与配置。
- **破坏（first-class）**：destruction harness，见下。

### 9.2 破坏测试矩阵（A2）

| # | 注入 | 断言 |
|---|---|---|
| D-1 | goal round 执行中 kill 进程 | 重启后 fold 重建的 GungnirState 与破坏前语义等价（未提交事件丢弃可接受，已提交事件一条不丢）；续轮从正确 action 开始 |
| D-2 | 外部修改目标文件（模拟环境漂移） | 下一轮 artifact verifier 得到 STALE/FAIL，触发 REPLAN 而非误 COMPLETE |
| D-3 | 工具执行失败注入 | FAIL 路径正确；transient 判定与 RETRY 上限生效 |
| D-4 | DSH 会话 resume（重启后 `--resume`） | ledger 重放、状态缓存失效重建、goal 续轮正常 |
| D-5 | 会话 compact 后继续 | 【M0 验证后定】事件不丢或 checkpoint 快照策略生效 |
| D-6 | 模型在 evidence 不足时声称完成 | reconcile 不产生 COMPLETE；A5 场景 |

### 9.3 生死实验协议（A3，M5）

- 任务集：20 个 = 10 coding（含修 bug、加测试、小重构）+ 10 research/文档（含需要外部信息的开放任务）。
- Ground truth：每个任务人工标注"实际是否达成 + 达成标准"。
- 指标：verdict 与 ground truth 一致率；假验收数（系统 COMPLETE 而实际未达成，权重最高）；resume 成功率；evidence 覆盖率（每个 criterion 的 verdict 有真实 evidence 支撑的比例）；token/轮次开销。
- 出口：一致率不达标即触发一阶段熔断（阈值见全阶段计划 §4.1），写复盘，不续命。

## 10. 风险与对策（一阶段专属）

| 风险 | 概率 | 对策 |
|---|---|---|
| pre-step waterfall 顺序与 goal-round-driver 冲突 | 中 | M0 实测；降级 `Agent.inject()`；最坏情况 Gungnir 自排轮（用自有 source，不冒充 human authority） |
| 自定义 durable 事件不被 strict replay 接受 | 中 | M0 实测；备选独立 storage ledger（fold 不变） |
| compaction 裁剪 ledger | 低–中 | checkpoint 快照事件策略；D-5 用例锁定 |
| LLM rubric 不稳定/被模型 prompt 攻击 | 中 | 强 schema + prompt hash + 阶梯强制规则（L4 不能单独判 PASS）+ A5 用例 |
