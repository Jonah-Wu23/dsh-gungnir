## 1. 目标与非目标

### 1.1 目标（全阶段 §4.2 八项的可执行形态）

1. **Verifier 阶梯补全**：新增 L3 external-state 与 L5 human verifier；阶梯强制规则升 v2（L4 降级精确化、human override 通道、COMPLETE 佐证规则 v2）；L4 rubric 缓存与管理。
2. **Verifier 终局闭环**（一阶段遗留缺口）：L4 被阶梯降级（raw PASS → effective PARTIAL）的 criterion 有显式 NEEDS_HUMAN 升级路径，不再耗进 BLOCKED(stuck / verifier-unresolved)。
3. **GoalSpec Compiler 轻量版**：决策相关澄清（单轮批量提问，不是十问面试）→ spec v2 → 单次确认提交。
4. **spec 变更语义**：version 递增的 in-run 变更 + fold 调和规则 + `/gungnir` 侧更新入口 + D-7 破坏用例。
5. **Plan invalidation 显式化**：`gungnir/invalidate` 事件留痕"为什么改"。
6. **Progress metrics（仅 evidence-derived）+ 熔断器完整版**（成本守卫的可观测性以 M0 结论为准）。
7. **GOAL_REVALIDATION 增强**：重查范围从 successCriteria 扩到带谓词的 constraints/invariants。
8. **WAITING_EXTERNAL**：区分"等外部事件"与"该继续推理"；等待期间 native goal 不空转，kill/resume 后等待可重建。

### 1.2 非目标（显式排除，防范围蔓延）

- Adaptive Runtime 完全体部分（六模式策略集、meta-controller、hysteresis 五件套、有限状态模板）在本文件内，但详细设计待三阶段启动时补写（全阶段 §4.3 已有范围）；Loop VM 不做。
- 多 goal、跨 session goal、多轮苏格拉底面试系统。
- UI cards、发布与生态（四阶段）。
- 任何对 DSH 核心包源码的修改（替换默认 loop 走组合接缝，不改源码，ADR-0012）。v0.1.2 适配（三处适配点）已前移至二阶段 M0（ADR-0011）。
- Contract VM / versioned execution graph（ADR-0003 已裁决不做）。
- **代码层语义猜测**：Verifier"选择器"只做结构性强制（kind↔level 一致性、降级、override 通道），不用关键词/正则嗅探 criterion 文本"该用哪级"（Let It Go 铁律）；"能低级就低级"的引导写进 spec 草案 prompt（模型侧引导），不落代码。

## 4. Ledger schema v2（M0 冻结）

纪律：**全部 additive**；KvUnit `version` 保持 1（破坏性变更才 bump 且须另行 ADR）；v1 事件必须能被 v2 fold 原样接受（兼容回归测试锁死）。

### 4.1 spec 侧扩展

- `GoalSpecSchema` + `userPreferences[]`、`invariants[]`（对齐 UltraGoal 文档 Goal Contract 字段表）。
- constraints/invariants 条目支持可选谓词形态 `{ text, predicate? }`：带谓词的参与机器重查（§7 REVALIDATION），纯文本的只列入完成报告的人审清单——绝不假装自然语言约束被机器证明了。
- `PredicateKindSchema` + `'external_state'`；`VerifierLevelSchema` + 3；`levelForKind` 增补 `external_state → 3`。
- `ExternalStatePredicateSchema`（草案，M0 冻结）：`{ kind, channel: 'web' | 'shell', url, expectStatus?, bodyContains?, timeoutMs }`。

### 4.2 verdict 侧扩展与降级精确化

- `VerifierKindSchema` + `'external_state' | 'human'`；verdict level 域拓宽为 1|2|3|4|5。
- **`effectiveOutcome` 修正**：降级规则从 `level >= 4` 改为 `level === 4`——L5 human PASS 是终局权威，不降级。一阶段 L5 无 verdict 通道，该修正在旧事件上等价无差。

### 4.3 fold 规则变化

- **human override**：`kind: 'human'` 的 verdict 可落在任何 kind 的 criterion 上（豁免 `foldVerdict` 的 kind 一致性强校验，level 恒 5）。outcome PASS → satisfied；FAIL → 以 `errorSignature: 'human-rejected'` 进入失败路径。这是"L4 无法终判"与"human 谓词"的统一出口（ADR-0013）。
- **spec 变更**：`gungnir/spec` 允许在 EXECUTING/VERIFYING 出现（一阶段仅终态可切，`SPEC_ENTRY_PHASES`），要求 specId 不变且 version = 前一版 + 1。调和规则：同 id 同 predicate 的 criterion 保留全部 verdict 状态；predicate 变化的重置该 criterion 状态（历史事件保留，状态重来）；消失的 id 置 tombstone（不再参与 `allSatisfied`）；新增 id 初始化为未决。version 断序/回退 → FoldError（ADR-0014）。
- **STATUS_EDGES + WAITING_EXTERNAL**：`EXECUTING/VERIFYING → WAITING_EXTERNAL`；`WAITING_EXTERNAL → EXECUTING`（decision 用既有 `RESUME`）/ `BLOCKED` / `NEEDS_HUMAN`。

### 4.4 新事件

| 事件 | payload 要点 | 说明 |
|---|---|---|
| `gungnir/invalidate` | `specId, projectionId, stepIds[], reason` | 显式作废投影（部分）前提，留痕"为什么改" |
| `gungnir/wait` | `specId, mode: enter \| exit, reason, condition: ExitCodePredicate \| ArtifactPredicate, exitCause?: condition-met \| timeout \| resumed` | WAITING_EXTERNAL 进出账；watcher 重建的唯一权威 |
| EvidenceSource + `'web' \| 'human'` | —— | L3/L5 verdict 的证据来源标注 |

### 4.5 progressSnapshot 扩展

仅 evidence-derived 可选字段（`verdictsByLevel`；`tokenObserved` 仅当 M0 证实可观测才加）。模型自估的 uncertainty / blocking-unknowns 只进 claim（advisory），不进 snapshot——不依赖"模型觉得自己有进展"。

## 5. Verifier 阶梯完全体

### 5.1 L3 External-state

- 通道决策【M0 验证 OPEN-3】：首选 `ctx.web.fetch`——v0.1.2 起公网 WebFetch 默认启用且内置 SSRF 防护（非公网地址抛 `WEB_BLOCKED_URL`，dsh-interface §15 新能力 3）；OPEN-3 从"0.1.1 有无 web 能力"改写为"**插件侧 `ctx.web.fetch` 可达性与 SSRF 边界实测**"（服务目录是否暴露 web 键、插件上下文能否注入、被拦地址的失败形态）。备选 shell 通道（`ctx.shell` 跑 pwsh `Invoke-WebRequest`，继承 sandbox 与超时语义，sandbox 拒绝/执行器故障 → INCONCLUSIVE，沿用一阶段 fail-loud 原则）。**路由规则：公网核验走 web 通道，localhost/内网核验恒走 shell 通道。**两通道结果都落 evidence（source `'web'`，digest + locator）。
- STALE 语义沿用一阶段：曾经 PASS 的外部状态复核失败 → STALE → 触发 REPLAN（决策表已有该边）。
- 核验失败（反爬/登录墙/超时）如实落 INCONCLUSIVE/FAIL，绝不兜底文本（Let It Fail）。

### 5.2 L5 Human

- `VerifyContext` + `askHuman(agentId, question): Promise<HumanAnswer>`；插件侧接 `ctx.userQuestions.ask`【已验证：仅 root agent 可调】。二阶段无 subagent 编排，goal round 即 root 上下文，限制不咬人；三阶段受限组合已登记（全阶段 §4.3 第 7 项）。
- 触发路径：reconcile 判 NEEDS_HUMAN 且存在 pendingHuman / L4-capped criterion → engine 经 hook 直接发起 ask（一阶段只注入"去问用户"的指令，二阶段变为真问）。
- 答落账：`kind: 'human'`、level 5 verdict（§4.3 override 规则）。**超时/拒答 → 不产生任何 verdict**，停留 NEEDS_HUMAN，由 `/gungnir resume` 或重问推进——绝不把无答当答。
- headless/实验：Config + `humanAnswers` 脚本化答案（对齐 `autoApproveSpec` 先例：启动者即授权人）。

### 5.3 阶梯强制 v2（reconciler.ts）

- L4 降级精确化（§4.2）。
- **L4-capped 升级守卫**：criterion `lastRawOutcome = PASS` 且 effective = PARTIAL（被阶梯降级）、重试预算耗尽后 → NEEDS_HUMAN(`l4-capped-unverifiable`)，不再落 BLOCKED(verifier-unresolved)。BLOCKED(stuck / no-progress) 只表示执行停滞——"判不了"与"做不动"在 blocker code 上严格可分。
- **COMPLETE 佐证规则 v2**（ADR-0013 默认提案）：goal 级 COMPLETE 要求全部 criterion satisfied；每条机器 criterion 有其声明级 PASS；每条 human/升级 criterion 有 L5 PASS。一阶段的 `deterministicPassSeen`（至少一条 L1/L2 PASS）保留为 goal 级佐证并拓宽口径为 L1/L2/L3（改名 `machinePassSeen`）。

### 5.4 L4 管理与成本

- rubric 缓存：key = prompt hash（`criterionId|rubric|threshold|subjectPath`，ADR-0008）+ subject 内容 digest；digest 未变且已有 verdict → 不重跑，新 verdict 引用缓存键。
- `maxVerifierRuns` 预算口径不变；rubric 调用记录 model id + prompt hash（一阶段已有）。

## 6. GoalSpec Compiler（轻量）与 spec 变更

### 6.1 澄清（视角 C 纪律）

- `/ultragoal` 流程扩展：模型草案 → **仅当存在"会改变下一步 / Verifier / 风险 / 成本"的不确定点时**，经 `ctx.userQuestions.ask` 单轮批量提问 → spec v2 提交（沿用单次确认，不变成多轮面试）。headless 走 `autoApproveSpec` + 任务文件自带答案。
- spec v2 新字段（userPreferences / invariants）由编译器引导填充，均可空。

### 6.2 spec 变更（ADR-0014）

- 入口：`/gungnir spec-update`（human 命令）+ `gungnir_submit_spec` 接受 version+1（校验 specId 相同、version 递增）。
- fold 调和规则见 §4.3；变更后的轮末 reconcile 强制 REPLAN 一次（旧投影的前提随 spec 失效）。
- 破坏用例 D-7：执行中用户改 constraints → 变更落账、受影响 criterion 重置、不误 COMPLETE。

## 7. Invalidation / progress / 熔断器 / REVALIDATION

- `gungnir/invalidate`：REPLAN 决策落账前先落 invalidate（projectionId + stepIds + reason）；`/gungnir status` / `/gungnir verdicts` 输出变更轨迹。
- Progress metrics：snapshot 扩展见 §4.5；`/gungnir status` 输出 m/n、verifiedArtifacts、roundsNoImprovement、verdictsByLevel。
- 熔断器完整版：现有守卫（maxRounds / maxVerifierRuns / roundsNoImprovement / consecutiveInconclusive）保留并回归；成本守卫【M0 验证 OPEN-5】——v0.1.2 带 `dsh-token-meter`（会话流精确 token 用量能力，dsh-interface §15），OPEN-5 从"0.1.1 是否可观测"改写为"**token-meter 插件侧可达性实测**"；可达则直接落 token 真口径，不可达才退"轮次 × verifier 次数"代理口径并写进 Known Limitations。
- **REVALIDATION 增强**：`finishRevalidation` 除 successCriteria 外，重跑带谓词的 constraints/invariants（verdict 的 criterionId 用 namespaced id，进 criteria map）；任一失败 → 回 EXECUTING 重规划（现有边）；纯文本 constraints/invariants 列入完成报告的人审清单。**时序约束（v0.1.2 现役）**：tool-goal 自主 complete/blocked 不再硬停 turn（wrapup 注入，dsh-interface.md §15 适配点②），REVALIDATION 触发必须等 wrapup 落盘——M0 适配窗口在真实 profile 复核。

## 8. WAITING_EXTERNAL（ADR-0015）

- 模型侧新工具 `gungnir_wait { reason, condition: exit_code | artifact 谓词, pollIntervalSec, timeoutRounds }`——等待条件必须是机器可复验谓词（claim ≠ evidence：不是"我觉得要等"，而是"这个谓词满足了就走"）。
- **进入**：engine append `gungnir/wait`(enter) + status WAITING_EXTERNAL + `ctx.goals.disarm(agent)`【已验证：disarm 只撤进程本地续轮授权】→ goal-round-driver 停止排轮，空转归零。
- **唤醒**：插件 watcher 按 pollInterval 用 verifyContext 复验 condition；达成 → `gungnir/wait`(exit, condition-met) + status RESUME → EXECUTING + `goals.resume` 重新武装 + inject 指令。超时 → exit(timeout) → reconcile 裁 REPLAN / NEEDS_HUMAN。
- **重建**：插件启动 / `agent/created` 时 fold 出 WAITING_EXTERNAL 且有未闭合 wait → 重建 watcher（kill 进程不丢等待）【M0 验证 OPEN-6：watcher 生命周期与 disarm/resume 实测语义】。
- native goal 映射：WAITING_EXTERNAL 期间期望 native = active(disarmed)；`goal/changed` 不一致报警表加该映射。

| **M5 实验与 stage report** | 预注册文档 → `tools/experiments` 跑批器扩展（分层任务集、ground truth 标注流程）→ 50–100 任务跑批 → 分层统计 → 熔断判定 → stage report + 三阶段计划修订输入 | 5 天 | B8 达成 |

总计约 23 天纯工期，业余节奏折合 4–6 周（对齐全阶段估算）。M0 的四个 OPEN 是全局风险点，放最前面烧掉。

## 10. 测试策略

- **单元（core）**：schema v2 往返 + v1 事件兼容回归；fold 新规则（human override、spec 调和、WAITING_EXTERNAL 边、version 断序拒绝）；决策表新分支全覆盖（L4-capped 升级、WAIT、佐证规则 v2）。
- **集成（dsh-plugin）**：真实 profile 冒烟沿用一阶段管线（`dsh --profile headless`）；新链路——澄清 → spec、spec 变更、wait 进出、human 问答（脚本答案）。禁止离线 mock 联调。
- **破坏矩阵新增**（沿用 tools/destruction）：

| # | 注入 | 断言 |
|---|---|---|
| D-7 | 执行中 spec 变更（用户改 constraints） | 变更落账；predicate 变化的 criterion 状态重置；不误 COMPLETE |
| D-8 | wait 期间 kill 进程 | resume 后 watcher 从 `gungnir/wait` 重建；条件达成仍唤醒 |
| D-9 | wait 超时 / 条件永不满足 | exit(timeout) → 正确决策；等待期 round 不增长 |
| D-10 | L5 拒答 / 超时 | 不产生假 verdict；停留 NEEDS_HUMAN |

- **实验协议（B8，M5）**：预注册文档先落盘再跑批——"可判定任务"定义、verdict 归类规则、任务集构成（必须含 ≥20% 纯语义判据 goal 与对抗用例）、指标定义、熔断对照。一阶段教训写入协议：假验收探针必须模型无关；research 任务不得为通过率收窄成 L2 可判。
- **指标**：per-level precision/recall vs 人工 ground truth；假验收数（权重最高）；replan 收敛（REPLAN 后到下一次 satisfied 增长的中位轮数）；初始计划原样执行率；WAITING_EXTERNAL 用例等待期 round 增量（期望 0）；resume 成功率；token/轮次开销。
- **出口**：对照全阶段 §4.2 两条熔断（success criteria 建不起来 / 初始计划原样执行率极低且 replan 不收敛）写判定结论，触发即停、写复盘，不续命。

## 11. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| `ctx.web.fetch` 插件侧不可达或 SSRF 边界不符预期 | 中 | OPEN-3 先烧（对 v0.1.2 构建实测）；双通道设计（web/shell）；都不可用时 L3 显式降级为"不支持 + spec lint 提示"，不伪造外部核验 |
| userQuestions 在 headless 无交互端 | 中 | `humanAnswers` 脚本化（实验）；交互 profile 真跑（冒烟）；OPEN-4 定失败形态 |
| token-meter 插件侧不可达 | 中 | OPEN-5 先烧；不可达则代理口径 + Known Limitations |
| watcher 进程级脆弱（kill/重启） | 中 | `gungnir/wait` 事件为唯一权威，启动重建；D-8 锁定 |
| spec 变更引发状态语义复杂化 | 中 | 调和规则从严（predicate 变即重置、version 断序即 FoldError）；ADR-0014 先行 |
| schema v2 破坏 v1 ledger | 低 | 只许 additive；v1 兼容回归锁死；破坏性变更才 bump unit version（另行 ADR） |
| L3 外部核验被反爬/登录墙挡 | 中 | 失败即 INCONCLUSIVE/FAIL 如实落账（Let It Fail），不兜底 |
| 八项并行范围膨胀 | 高 | 里程碑串行 + 时间盒；超支砍项顺序：M3 成本守卫 → M2 澄清（保 spec 变更）→ M4（保阶梯与实验） |
