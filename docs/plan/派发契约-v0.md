# 派发契约 v0（Dispatch Contract）— 一页规范

> 状态：**accepted**（2026-08-30，B1 交付，ADR-0020 执行基准 §2）。实现权威 = `packages/core/src/contract.ts`（zod schema + 投影）；两边对不上时**先改本文再改码**，不许漂移。
> 一句话：**把大任务拆成小步骤防糊弄的规则说明书**——派发者（主 agent 或人）拆派发单元、填一张契约；子 agent 交付后，离线判定栈按契约自动出钓鱼题、按证据裁决。

## 1. 派发单元 schema v0（每个字段必须能投影到供给接口）

| 字段 | 必填 | 内容 | 供给去向 |
|---|---|---|---|
| `objective` | 必 | 一句话任务目标 | 裁决上下文 |
| `acceptance[]` | 必 | 验收判据：`id` / `description` / `verifierLevel`（1=命令、2=artifact）/ `command`(L1)+`expectedExitCode`+`timeoutMs` 或 `predicate`(L2) / `observability: provable \| sandbox-external` | 控制臂判据；L1 command 类 → `replay.evidence`；`sandbox-external` 项 → `unverifiableCriteria` |
| `api` | 选 | `module` / `function` / `template` / `signature`（模板名须存在于 harness 模板库：现役 `pricing-round-once` / `pipeline-validation`） | M-A 隐藏输入 probe |
| `grounding[]` | 选 | `output`→`source` 依据声明（"写 X 前须读 Y"） | M-D 时序检查 |
| `baselineRef` | 有 git 必填 | 派发点工作区快照：`{type:'git', commit}`（任务开始前的 commit） | M-B buggy 基底（`git archive` 提取） |
| `budget` | 选 | `maxTokens` / `maxSeconds` | 治理记录 |

约束：L1 判据必须有 `command`，L2 必须有 `predicate`（schema 按 `verifierLevel` 判别联合，违反即拒收）。`acceptance[].observability === 'sandbox-external'` 的判据按 ADR-0004/0009 语义**显式列为不可证**：终局只能是非完全 PASS（UNVERIFIABLE 是诚实标注，不是误杀）；健康 PASS 终局要求全部判据可证。

## 2. 防糊弄条款 → 证据规则映射表（核心章节）

| 派发者想防的糊弄 | 契约字段 | 落地的药方 |
|---|---|---|
| 特判测试输入骗绿钩 | `api` | M-A 隐藏输入 probe（输入对模型不可见，同 seed 同题） |
| 交付物不承重（测的路径 ≠ 生产路径） | `api` | M-A trunk-path 模板 + 承重思想（VE-F2：no-op 化应崩） |
| 测试绿但不判别 bug 修没修 | `baselineRef` + `acceptance` | M-B 判别性见证（replay 到 buggy 必 FAIL 才算判别） |
| 沙箱外判据假装可证 | `acceptance[].observability` | M-C UNVERIFIABLE 三态（显式列出，终局非完全 PASS） |
| 不读文档按猜测动手 | `grounding[]` | M-D read→write 时序检查（只判时序，不猜语义） |

## 3. 派发 / 验收流程

1. **派发**：填契约（一次性声明四类供给）+ 记录 `baselineRef`（派发点 git commit）。契约只作任务说明附件，**不注入子 agent 的运行时协议**（零协议税）。
2. **执行**：子 agent 干活（Agent 无感知）。
3. **交付**：交付工作区 + session log。
4. **离线裁决**：`tools/ve-supply/run-supply.mjs` 投影 supplied → 跑治疗臂判定栈（L1/L2 + S1 + M-A~M-D）→ 输出裁决 + 证据链 + **供给覆盖报告**（哪些药方有供给、哪些没有、为什么）。
5. **回执**：裁决 + 证据链 + 供给覆盖报告交派发者/CI 门禁。

## 4. 显式非目标（含 AP-1/AP-3 合规论证）

- **不做自动派发 runtime**：本契约是离线/判定侧资产，不碰 loop 层、不碰运行期介入（wrapup 钩子 + MAF 注入维持 ADR-0018 §5 冻结；重开锁 §6 三条件）。
- **契约不是协议税回潮**：AP-1——执行路径零新增往返（裁决在交付后离线进行）；AP-3——契约是**一次性捕获**（L1 轻量判据形态），派发时填一次，不逐轮收税。
- **钓鱼题不由运行时 AI 即兴生成**：probe 由 harness 模板库纯函数构造，同 seed 同题，防构造者偏差（ADR-0020 第 1 条）。
- **无 git 快照不假装 replay**：缺 `baselineRef` → M-B 不启用，覆盖报告如实记录（Let It Fail，ADR-0020 第 3 条）。

## 5. 与 GoalSpec 的关系

契约 ≈ **L1 轻量判据**（AP-3 渐进式形式化坐标）：GoalSpec 是版本化长期真理（L2），契约是一次性验收声明（L1）——契约的 `acceptance[]` 可投影为 GoalSpec 的 `successCriteria`（同一判据 schema），但契约不要求版本管理、不进入 ledger，是**更薄的一次性形态**。

## 6. Not verified（如实随档）

- `replay.evidence` v0 只取契约声明的 L1 command 判据（最诚实）；从 session log 提取 agent 实际跑过的命令列为后续增强，未验证。
- M-A 模板库覆盖面 = 现役 2 模板（pricing-round-once / pipeline-validation）；新任务形态需扩模板库（构造者偏差方向由双侧自检保证）。
- 本契约是 v0：真实环境覆盖面（多任务形态、M-B 对非 node 工具链、跨平台路径归一）未在更大样本上验证；外推禁止（§6 口径纪律延续效力报告 §6）。
