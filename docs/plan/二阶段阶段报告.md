## 1. 结论（先说判定）

**冻结门判定：FAIL（0/4 达标）→ 触发预注册熔断出口（§5.5a）：暂停"替换默认 loop"路线，回退方案 B（seam 控制平面降级形态保留）。**

任务成功率不下降这一半门条件达成（Gungnir 6/6 = Code-PTC 6/6，无质量回归、无假验收），但 Adaptive Loop v0 在本实验任务面上的全部四项成本指标反向劣化，无一达标：

| 指标（Gungnir vs Code-PTC，中位） | 结果 | 阈值 | 判定 |
|---|---|---|---|
| task success | 6/6 vs 6/6 | 不下降 | ✓ 达成（门的前置条件） |
| input tokens（下界估计） | 9449.5 vs 5884.5 → **+60.6%** | ↓≥20% | ✗ |
| LLM round-trips | 13.5 vs 4 → **+237.5%** | ↓≥25% | ✗ |
| wall-clock | 102.4s vs 15.1s → **+579.9%** | ↓≥15% | ✗ |
| 重复无效步骤 | 8 vs 1 → **+700%** | ↓≥30% | ✗ |

四组基线自身质量对比：standard / ptc / workflow 全部 6/6 成功；workflow 组在提示明示可用 workflow 工具的情况下未表现出对 standard 的效率优势（中位 wall 反而略高）。

## 2. 判定有效性核查（task-verifier 纪律）

- **数据完整性**：24/24 run 全部落行；四组各 6；session log 全部反查解码成功（sessionLocated=6/6 每组）；无 runner 超时；全部 runner exit 0。
- **指标口径**：全部按预注册 §4 操作化——token 为官方 tokenizer 离线估计（`plain_text` 法，请求可见面重建，**系统性下界**且偏差同向作用于所有组，组间可比）；gungnir 组另有 tokenMeter usage 锚点日志可校准；cache hit 离线不可观测记 null 未进门（预注册声明）。
- **公平性边界（预注册声明，非偏差）**：gungnir 组的 Gungnir 流程指令（draft spec → gungnir_submit_spec → round flow）是其产品设计用法的一部分，开销计入该组。
- **跑批前偏差（冒烟期修正，官方 24 run 批次零改动）**：t6 谓词与目标字符串一致化（`"a":1` 无空格）；judge cwd 限定 run 工作区；`rmSync`/token 文本接线补齐。三项均在冻结批次启动前修正并有冒烟记录。
- **结论稳健性**：本结果与 SwitchBench v0（ADR-0013，5 小型任务面）方向一致且量级更大——两条独立证据线共同指向：**小型任务面上，Gungnir 协议仪式（spec/plan/report/verdict 循环）的固定开销不回本**。gungnir 组每个任务固定多出约 1 次 validation failure（模型先跑暴露 bug 的测试/检查，属于如实判定的成本，非作弊）。

## 4. 熔断后的处置（按预注册执行，不做"再加一个 patch 试试"式续命）

1. **替换默认 loop 路线暂停**：`gungnir-loop` 包与替换机制（ADR-0014 两步法，已实证可行）作为**资产保留**，不再向前投入；`gungnir-loop` profile 降为实验/开发用途。
2. **回退形态**：方案 B（seam 控制平面）为预注册退路（全阶段计划附录 A）；其投资同样已被 ADR-0013 冻结——即两条"运行中换 loop 拓扑"的路线均告一段落，**Gungnir 的 Prove 层（证据/裁决/调和）保持现役**，继续跑在默认 driver 上（一阶段形态）。
3. **重开条件（证伪即重开，沿 ADR-0013 修订第 9 条口径扩展）**：当出现**大型/跨模块/错误来源不明确**的任务面证据（SwitchBench 判词 §5.6 的 SHOULD-escalate 正样本组），或 DSH 官方给出 loop 内建自适应方向时，以新实验重开评估；届时 router v0 与三模式机制资产可直接复用。

## 5. 输入三阶段计划修订的结论

- Proof-Carrying 支柱（五级阶梯、GoalSpec Compiler、WAITING_EXTERNAL 等）与 loop 路线**无耦合**，可按原三阶段计划独立启动（Prove 层继续在默认 driver 上演进）。
- Adaptive Runtime 完全体（六模式、meta-controller、hysteresis 五件套、有限状态模板）在三阶段内**降级为观察项**：其启动前提（本实验通过）未满足。
- 新增设计输入：Gungnir 的价值假设必须先在"成本可回本"的任务面上证成（Router 判断"何时不介入"的能力是第一优先实验，ADR-0013 修订第 6 条）；v0 的教训是**协议仪式本身即成本**，任何重开实验的对照组应包含"Gungnir Prove 层跑在默认 driver 上"（即一阶段形态 + 更强 router 提示），而非只对照原生 DSH。
